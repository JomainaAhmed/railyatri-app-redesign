# RailYatri App Redesign — UX Case Study

> An end-to-end redesign of RailYatri, one of India's leading train-travel apps — from market research and user personas through high-fidelity UI and prototyping.

## Overview

Indian Railways serves over 23 million passengers daily across 7,000+ stations. RailYatri, an IRCTC-authorized platform with 5 crore+ installs, is a major player in this space — but user reviews and a 2022 data breach affecting 31 million users point to real gaps in usability, reliability, and trust.

This project redesigns the RailYatri experience through a user-centered process: identifying usability gaps, benchmarking against competitors (IRCTC Rail Connect, ixigo, ConfirmTkt), and proposing solutions that improve usability and rebuild trust — without breaking what already works for 5 crore existing users.

## Process

1. **Research** — Market sizing and trend analysis, competitive analysis (direct & indirect competitors), and benchmarking against best-in-class flows (Ixigo's predictive search, RedBus's seat-selection clarity, Paytm's UPI speed).
2. **Understand Users** — Ethnographic research distilled into four personas (Commuter Professional, Student Traveler, Family Planner, Occasional Traveler), each with distinct goals, pain points, and tech familiarity — plus a 7-stage customer journey map (Awareness → Consideration → Booking → Pre-Travel → Travel → Post-Travel → Loyalty).
3. **Define** — A retain/improve/new framework for every feature decision, each with an explicit rationale, feeding into an information architecture built around 5 primary app sections.
4. **Design** — 5 core user flows (ticket booking, live train status, in-train food delivery, community/group chat, women-safety SOS), a mood board, and a style guide (Poppins type system), moving from paper wireframes to high-fidelity Figma screens.
5. **Prototype** — An interactive Figma prototype covering onboarding, login/OTP, home, bookings, live tracking, and the full ticket-booking flow including error and confirmation states.

## Key Design Decisions

| Decision | Why |
|---|---|
| Retained core booking, PNR/status tracking, food delivery | High-usage, trusted features — redesign focused on usability, not reinvention |
| Redesigned navigation, booking cards, notifications, added dark mode & offline access | Reduce friction on read features (late-night travel, poor connectivity) |
| Added Women Safety/SOS + Trust Circle | Directly addresses the trust gap surfaced by the 2022 breach and ethnographic research |
| Added Community/Group Chat + Smart Coach Navigation | Reduces real-world coordination and wayfinding friction at large stations |
